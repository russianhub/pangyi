# 旁译 v4.17.0｜输入更干净，常用词俄语更正

这次更新修了六处输入边界，并用 127 条手写俄语盖住抽查里影响最大的一批错译。词典文件本身没有改。释义抽查、数据怎样编进输入法，以及打标签后的发布流程，也写进了文档。

**[下载 Windows 安装包：pangyi-v4.17.0.exe](https://github.com/russianhub/pangyi/releases/download/v4.17.0/pangyi-v4.17.0.exe)**

安装包已经挂在这个 Release 上，可以直接下载。安装包未签名。

## 输入修复

来自 [PR #4](https://github.com/russianhub/pangyi/pull/4)。拼音顶行、义项滑动窗、光标编辑、表情候选都保持原样。

1. **只有主键盘 A–Z 算拼音字母。** 小键盘、功能键，以及键码截断后会变成字母的扩展键，不再写进拼音。正在打字和没在打字时都一样。
2. **宿主结束组合时清干净。** 拼音、光标、候选和句子缓冲一起清掉。自己已经上屏或取消的组合不会被误清；旧组合迟到的通知不能取消更新的组合。读选区、写文本、结束组合都在组合锁外面做。
3. **没有候选时，确认键和导航键各走各的。** Tab、↑、↓ 不拦截，交给应用。回车和空格把原始字母上屏并结束组合，不写入 `learned.txt`。←、→、Delete、Home、End 在拼音里仍然移动光标。
4. **点选只落在画出的内容上。** 只有可见候选，以及这一行实际画出的释义，才会上屏。空释义、藏起来的行、窗口外和页脚点了不上屏。横排不再把整行都当成第一条。
5. **候选窗跟光标所在的屏幕。** 用该显示器的工作区摆放。副屏和负坐标不再被夹回主屏，也不钻进任务栏。
6. **上屏用当前行已经解析好的释义。** 多音字不再按汉字回词典另找一条读音。这一行没有释义时回退汉字本身，不借另一条读音。表情的逐字模式不变。

## 127 条手写俄语覆盖

来自 [PR #6](https://github.com/russianhub/pangyi/pull/6)。表在 [`data/gloss-overrides.tsv`](https://github.com/russianhub/pangyi/blob/main/data/gloss-overrides.tsv)，编译期嵌进输入法。候选和逐词翻译取俄语时，按「简体 + 读音」整条换掉 `ru`。词头、拼音、词频、来源不动，所以自学习（`learned.txt` 按中文词头记）、自定义短语和缩写键不用跟着改。`dict.tsv` 和 `lm.tsv` 没有改。

| 分类 | 条数 |
| --- | ---: |
| 虚词与高频功能词 | 17 |
| 多音字分读音 | 57 |
| 枢轴错义与错的首义 | 24 |
| 短语拆碎与空释义 | 21 |
| 其他高频错译 | 8 |
| 合计 | 127 |

| 词 | 读音 | 覆盖之后 |
| --- | --- | --- |
| 的 | de | 结构助词，不再是鲜明、白额马、箭靶 |
| 没 | méi | 不、没有，不再是去世 |
| 长 | zhǎng | 生长、年长、首长，不再和 cháng 共用「长的」 |
| 事业 | shìyè | 事业、职业生涯，不再是殡葬服务 |
| 承诺 | chéngnuò | 答应、义务，不再是汇票承兑 |

同一「简体 + 读音」后一行生效。列数不对、空词头、空释义、空说明、没有西里尔字母，或者词头、读音在词典里对不上，测试会整表失败，不会跳过。这张表是原创，随数据按 CC BY-SA 分发，见 [NOTICE.md](https://github.com/russianhub/pangyi/blob/main/NOTICE.md)。它不能单独造一个词典里没有的词。

把握不如其余条目、但已经写进表里的：是从、那 nuó、着 zhāo、得 dé、为 wèi、和 hú、句 gōu、吧 biā、曾 zēng。没有写进去的：榜 péng、落 lào、将 qiāng、听 yǐn。

## 新文档

来自 [PR #5](https://github.com/russianhub/pangyi/pull/5)。这次发布没有改判定，也没有重跑脚本，下面的数字是该 PR 记录的结果。

- [常用词俄语释义抽查](https://github.com/russianhub/pangyi/blob/main/docs/gloss-audit.md)：按 `ime/src/dict.tsv` 里的 jieba 词频取前 5,000 个简体词头。4,981 / 5,000（99.62%）有西里尔俄语。固定种子抽出 200 个词，判定为正确 113、可接受 56、义项错误 19、垃圾或空白 12。抽样不按词频加权，所以漏掉了「的」「没」这种最高频的错译；那些词由上面的覆盖表处理。
- [数据流水线](https://github.com/russianhub/pangyi/blob/main/docs/data-pipeline.md)：每个来源的许可、哪个脚本写出哪个文件、`include_str!` 怎样嵌进 DLL，以及仓库里复现不了的步骤。
- [`tools/audit_glosses.py`](https://github.com/russianhub/pangyi/blob/main/tools/audit_glosses.py) 可以按当前词典重算覆盖率，并核对那 200 个词的判定是否还对得上这次抽样。

## 持续集成与发布

来自 [PR #3](https://github.com/russianhub/pangyi/pull/3)。推送 `v*` 标签时，[release.yml](https://github.com/russianhub/pangyi/blob/main/.github/workflows/release.yml) 跑和 CI 同一套构建，把安装包命名为 `pangyi-<标签>.exe`，并写一份 `sha256sum -c` 能用的 `.sha256`。说明正文用 `docs/releases/<标签>.md`。标签已经有 Release 时工作流会失败，不覆盖附件。用的是 Actions 自带的 `GITHUB_TOKEN`。

这次 `v4.17.0` 的实际情况：

- 标签先打在 `ae852de`（[PR #7](https://github.com/russianhub/pangyi/pull/7) 的压缩合并）。[Release run 41826308495](https://github.com/russianhub/pangyi/actions/runs/41826308495) 在检查「这个标签还没有 Release」时失败：`gh release view` 发现没有 Release 会退出 1，脚本把这当成成功，但这个退出码留在进程里。安装包没有生成。
- [PR #8](https://github.com/russianhub/pangyi/pull/8) 修好了这条路径（确认没有 Release 之后 `exit 0`；已有 Release 或缺少说明文件仍然失败）。压缩合并是 [`1f7867d`](https://github.com/russianhub/pangyi/commit/1f7867d6aa01d1c413c5af8bb3b39639a8adc118)。标签挪到这个提交，名字仍是 `v4.17.0`。
- 第二次 [Release run 41828497595](https://github.com/russianhub/pangyi/actions/runs/41828497595) 通过，用时 2 分 27 秒，上传了下面的安装包和 `.sha256`。

版本号只写在 [`ime/Cargo.toml`](https://github.com/russianhub/pangyi/blob/main/ime/Cargo.toml)。安装程序写进 `version.txt` 和「设置 → 应用」里的 `DisplayVersion`，资源里的 `FileVersion` / `ProductVersion`，都从 `CARGO_PKG_VERSION` 来。工作流不写死 `4.17.0`。

## 怎么使用

1. 下载并运行本页安装包。安装包未签名。若出现 SmartScreen 提示，先确认来自本仓库的 Release，并核对本页的 SHA256。
2. 从旧版升级时，保存工作，完全退出并重开使用旁译的应用（包括后台进程）。若仍像旧版，注销后重新登录。
3. 打 `de`，看「的」的俄语不再是鲜明、白额马。打 `mei`，看「没」不再是去世。
4. 记事本里打 `ni`，候选出现后再按小键盘和 F5，拼音应不变，这些键交给应用。

## 需要重启吗？

| 场景 | 需要做什么 |
| --- | --- |
| 首次安装 | 按安装提示注销并重新登录，或重启电脑，完成系统输入法加载 |
| 从 v4.16.0 或更旧升级 | 保存工作，完全退出并重开使用旁译的应用（包括后台进程）；若仍未更新，注销后重新登录 |
| 日常开启/关闭英文模式、表情模式 | 无需重开应用或重启电脑，通常约 0.5 秒内生效。这是 v4.16.0 已有的行为，本版没有改这两个开关 |

热重载不能代替升级后的组件重载。应用要先加载 v4.17.0，覆盖表和输入修复才在那个进程里。

## Known limitations / needs manual Windows verification

已知限制：下面几项还需要在 Windows 上手工看，不能靠这次的单元测试代替。

- **只有单元测试。** CI 跑的是 `cargo test --locked` 和编译。没有在装了旁译的 Windows 上、用记事本或浏览器把输入走一遍。
- **32 位 DLL 没有在 32 位进程里加载过。** CI 会检查它是 PE 机器类型 `0x014C`、导入 `msvcrt.dll`、不导入 `libunwind.dll`。检查的是文件头和导入表，不是在 32 位进程里 `LoadLibrary`。`windows-latest` 是 64 位系统。

手工验收清单在 [PR #4 的「手动验收（Windows）」](https://github.com/russianhub/pangyi/pull/4)。原文如下，仍应在一台装了旁译的 Windows 上逐项看：

- [ ] 记事本或浏览器输入框里打 `ni`，候选出现；按小键盘 1 和 F5，拼音不变，键交给应用。
- [ ] 打一串词典里没有的字母（例如 `zzzzzz`），按 Tab，焦点离开输入框；再打一遍，按回车和空格，原文上屏，组合下划线消失，后面再打字不会盖住它，`learned.txt` 不出现这串字母。
- [ ] 打 `zhong`（或能出两个「重」的音节），用 → 选不同义项后上屏，俄语是当前行的义项，不是另一个读音。
- [ ] 竖排候选：点词、点短释义、点释义右边的空白、点页码药丸、点窗口外面，只有词和释义本体上屏。
- [ ] 横排候选：点第 2、第 3 条，上屏的是点中的那条，不是第 1 条；点释义那一行和卡片外不上屏。
- [ ] 把窗口拖到副屏（含左侧负坐标），候选窗跟光标走，不被夹回主屏，也不钻进任务栏。
- [ ] 打到一半按 Esc，或让宿主自己结束组合（切走焦点/清空），候选窗收起，再打新的拼音不受上一次影响。
