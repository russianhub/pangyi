# 设置窗口重做：许可证核查与设计说明

状态：步骤 1，只做审查和设计。本文不改 Rust、Cargo、CI、词库或 Release。

结论先说：

- **没有必须停工的许可证冲突，也不换方案。** 旁译代码是 MIT。Slint 1.19.0 是三选一许可。设置程序是装在普通 Windows 电脑上的独立桌面程序，不是嵌入式系统。步骤 2 默认走 **免版税协议（Royalty-free 2.0）**，旁译自己的源文件继续 MIT，关于页放 `AboutSlint`。GPLv3 也走得通，但会让「链接了 Slint 的那个 exe」整包按 GPL 分发。两条路都要等维护者确认，见文末。
- **没有必须停工的技术阻碍。** 设置程序只编 64 位 MSVC，不编 32 位。窗口用 Slint 的 `fluent` 样式。渲染用 winit + FemtoVG，不用软件渲染器当中文主路径。体积是上游讨论里的估算，本仓库没有实测。
- **本文全部来自静态阅读仓库和上游许可/文档。** 没有在 Windows 上编译、运行或截图。

审查时 `main` 与 `origin/main` 同为 `c25c5c4`。

## 2. Slint 三条许可，和本仓库怎么对得上

核对时间：2026-11-24。上游版本以 crates.io 上的 **slint 1.19.0**（2026-11-16 发布）为准。

crates.io 许可表达式：

```text
GPL-3.0-only OR LicenseRef-Slint-Royalty-free-2.0 OR LicenseRef-Slint-Software-3.0
```

上游 `LICENSE.md` 和 FAQ 写明：三条里任选一条。自己的源文件可以继续是 MIT 或 Apache-2.0。Slint 本身不因此变成 MIT。

### 2.1 GPLv3

适用：开源程序，桌面、移动、网页、嵌入式都可以，不收费。

和本仓库的关系：

- MIT 与 GPLv3 兼容。Slint 官方写明，选 GPLv3 时旁译自己的文件头可以继续是 MIT。
- 兼容的含义是：分发「链了 Slint 的那个程序」时，**这个程序整体按 GPLv3 给接收者**。接收者要能拿到对应源码、看到版权和「没有担保」的说明，并且不能再加更严的限制。
- 输入法 DLL、安装程序源码、更新程序，只要不链接 Slint，就仍然只是 MIT。GPL 不会顺着「同一个安装包里放了另一个 exe」自动爬进 DLL。前提是设置程序单独成进程，安装包只是把文件拷到磁盘（聚合），而不是把 Slint 编进 DLL。
- 以后若用 `include_bytes!` 把设置程序嵌进 `setup.exe`，安装包二进制里会含有一份 GPL 程序。这是步骤 3 要避开的做法：设置程序作为旁边的独立文件安装，不嵌进安装包字节。
- 仓库顶上的「代码：MIT」在设置程序发布时必须改成「旁译代码 MIT；`pangyi-settings.exe` 因链接 Slint，整体按 GPLv3 分发」。那是实现 PR 的说明义务，不是现在就要改 README。

合规条件：关于页写明版权、无担保、协议文本在仓库里、对应源码随公开仓库的同一标签提供。不要把 Slint 的源码声明改成 MIT。

### 2.2 免版税协议（Royalty-free 2.0）——步骤 2 的默认假设

适用：桌面、手机、网页程序，不收费，不覆盖嵌入式。上游对「嵌入式」的定义是装在更大机械或电气系统里、只干一件专门事情的计算机。旁译设置程序是用户自己 Windows 电脑上的普通程序，对得上「桌面程序」。

义务（做到一条即可）：

1. 在能从程序顶层入口打开的「关于」界面里放 `AboutSlint`（`std-widgets.slint` 里的 “Made with Slint” 徽章）。没有关于界面时，才要求放在启动闪屏上。
2. 或者在公开下载页放 Slint 徽章。

本设计采用第 1 条：左侧「关于」就是这个程序的顶层入口，关于页放 `AboutSlint`，不做启动闪屏，也不在候选窗里放徽章。

限制：

- 不能把 Slint 单独拿出去发布（要单独发布就改用 GPLv3）。
- 不能用在嵌入式系统里。
- 不能让设置程序把 Slint 的 API 再暴露给别人。
- 不能删改 Slint 源码里的版权和免责声明。

和「无广告、无遥测」的关系：徽章是协议要求的署名，放在关于页，不是候选窗广告，也不是联网统计。输入法 DLL 仍然不引用 Slint、不联网。这一点需要维护者点头；若认为徽章本身就不能出现，就改走 GPLv3（不要徽章，但 exe 整体按 GPL 分发），或者购买商业许可。这三选一，不构成「Slint 不能用」。

fork 的人可以给自己的程序另选三条许可之一。旁译仓库选择免版税，不妨碍别人在 fork 里改选 GPLv3。

### 2.3 商业许可（Slint Software License 3.0.5）

要按席位付费。桌面程序在已经满足免版税或 GPLv3 时用不到它。嵌入式商业产品才必须买它。旁译不是这种产品。本文不建议购买。

### 2.4 和 CC BY-SA 词库的边界

设置程序**不能**依赖 `pangyi_ime`，也不能 `include_str!` `dict.tsv` / `lm.tsv`。那会把词典数据编进设置程序，体积回到几十 MB，并且让这个 exe 变成 CC BY-SA 数据的衍生品。词库条数不要靠链接输入法去数。见第 6 节。

### 2.5 因此不换方案

三条许可里至少有两条能用，官方明确允许旁译源文件保持 MIT。默认假设是免版税 + 关于页 `AboutSlint`。这不是临时换掉 Slint，而是在已定的 Slint 方案里选定哪一张许可。维护者若改选 GPLv3，界面规划不用重做，关于页的法律文字改掉即可。

## 3. 技术可行性

同样只根据上游文档和本仓库 CI，没有在 Windows 上编过 Slint。

### 3.1 要编哪种二进制

| 产物 | 现在的 CI | 设置程序要不要跟着编 |
| --- | --- | --- |
| `pangyi_ime.dll` 64 位 | `windows-latest` 默认 MSVC，`cargo build --release --lib` | 不要。DLL 不链 Slint |
| `pangyi_ime.dll` 32 位 | `i686-pc-windows-gnu` + llvm-mingw 20261020，`+crt-static` | 不要。设置程序不注入 32 位进程 |
| `setup.exe` | 64 位 MSVC。`build-windows.ps1` 用 `Assert-Pe ... 0x8664` 检查 | 步骤 2 不改安装包 |
| `pangyi-updater.exe` | 64 位 MSVC | 继续独立，设置程序只去启动它 |

32 位 DLL 是给 64 位 Windows 上的 32 位应用加载输入法用的。安装包本身是 64 位。设置窗口没有「必须有 32 位 exe」的现成要求。上游没有承诺 Slint 能用本仓库这套 llvm-mingw 交叉编过 `i686-pc-windows-gnu`。不编 32 位设置程序，这条就不构成阻碍。若以后要支持纯 32 位 Windows 操作系统，再单独立项。

### 3.2 后端和渲染

上游默认是 winit，渲染器默认同时打开 FemtoVG 和软件渲染器。文档还提供 Skia、Skia 软件路径、FemtoVG 的 wgpu 路径。

步骤 2 的假设：

- 样式：编译期用 `fluent`（Windows 上 `native` 也是它）。不要编译成 `fluent-light` 或 `fluent-dark`，那两档会把深浅色焊死。
- 运行时深浅色：`Palette.color-scheme`。`unknown` 跟随系统，`light` / `dark` 对应设置里的强制浅色、强制深色。上游讨论写明 1.15.1 起可以从 Rust 设置这个值；1.14.1 不行。1.19.0 在这条线之后。
- 渲染：只要 `backend-winit` + `renderer-femtovg`。FemtoVG 走 OpenGL。
- **不要把软件渲染器编进去当退路。** 上游写明软件渲染器的文字目前限于西文。旁译界面是中文，静默退到它上面会缺字。机器没有可用的 OpenGL 时，程序应当直接说明打不开，而不是画出残缺界面。
- 无障碍 feature 保留。上游维护者明确不建议关掉。
- 不启用 Qt、Skia、wgpu，除非后面证实 FemtoVG 在目标机器上不可用。

Fluent 是 Slint 仿 Fluent Design 的控件皮肤，不是 WinUI 3，也不是系统自带的设置应用。圆角、分段按钮、开关可以用这套皮肤做。亚克力、Mica 不在本步骤的承诺里。

`Palette` 文档里对 `dark` / `light` 的英文说明看起来像写反了（写着 dark 用浅色背景）。步骤 2 必须在 Windows 上目视确认：选「深色」时背景是深的。本文不把那句英文当成已经核对过的行为。

### 3.3 DPI、字体、深浅色

- 窗口逻辑尺寸约 820×560，最小 720×480。DPI 交给 winit。不要再手乘一遍 DPI，否则会和 Slint 的缩放叠成两次。
- 字体按规格：界面用 Segoe UI Variable，中文回落到微软雅黑 UI。现有 GDI 面板和候选窗只用微软雅黑 UI，没有 Segoe UI Variable。Slint 的 `default-font-family` 若只能写一个家族，中文就用微软雅黑 UI，西文标签再单独指定 Segoe UI Variable。这一条必须在 Windows 上看实际回落，本文未验证。
- 候选窗预览用的是第 5 节的旁译色值，不是 Fluent 调色板。Fluent 只负责设置窗口自己的控件。五套配色不把整个设置窗口染成青、粉、橙、紫、绿。规格里的「即时变化」指外观页顶部的预览。

### 3.4 体积（估算，不是实测）

上游维护者和用户在 2023 到 2025 年的讨论里，Windows 上大致是：

- 空窗口 + FemtoVG，开 LTO 和 strip：大约 2.6–3.6 MB
- 带一些控件的小程序：大约 6–7 MB
- 换 Skia：大约再多 20 MB 这一档

本仓库没有编过，所以不能把这些数字当成旁译设置程序的测量值。步骤 2 用 `opt-level = "z"`、`lto = true`、`strip = true`（与 `updater/Cargo.toml` 同一档）之后，再在 CI 日志里记一次真实字节数。

相对现在的安装包：CI 只要求 DLL 各至少 20 MB、安装包至少 40 MB。任务说明里的「两份 DLL 约 66 MB / 69 MB、安装包可能超过 100 MB」**不是本文量出来的**。一个大约数 MB 的设置程序，即使用 `include_bytes!` 嵌进安装包，也只占安装包的一小截；步骤 3 仍建议单独落盘，不嵌进去。编译时间会变长。现有 Windows 任务的超时是 240 分钟，从数字上看放得下，但是否拖慢要等步骤 2 的第一次 CI，不能事先说没问题。

### 3.5 工具链

slint 1.19.0 的 MSRV 是 Rust 1.95。CI 使用 `stable`，没有钉版本。本文没有去翻 Windows 运行器上的 `rustc --version`。按 Rust 的发布节奏，2026-11-24 的 stable 应当已经高于 1.95；这是推断。步骤 2 第一次编译若因 MSRV 失败，再钉工具链，不在本文里改 workflow。

## 4. 和「已知情况」不符的地方

下面每条都是仓库里的实际样子。

1. **版本。** `ime`、`account`、`updater` 的 `Cargo.toml` 都是 `4.19.0`。`README.md` 的下载按钮仍指向已发布的 v4.18.0。`docs/releases/v4.19.0.md` 已在仓库里。设置窗口标题用的是编译它的那个包的 `CARGO_PKG_VERSION`。
2. **没有根 workspace。** `updater/Cargo.toml` 自己有一个 `[workspace]`，用来阻止 Cargo 向上找。`account` 和 `ime` 是分开的包。`ime` 用 feature `account` 可选地引用账号库，而且注释写明 `cargo build --lib` 不带这个 feature。
3. **设置不全在 `settings.txt`。** 自动更新在 `updater.json`。账号令牌在 `account.dat`。短语、用户词、自学习、表情包都是旁边的文件。旧的 `layout.txt` 仍会被读一次。
4. **热重载只有英文模式和表情模式。** 其余键在别的进程里改了，正在打字的程序不会马上变。详见第 6 节。规格里的「即时生效」对候选窗并不成立；外观页里的预览可以即时，因为它画在设置程序自己的窗口里。
5. **`save()` 会整文件重写。** 不认识的键、注释、空行都会丢掉。`debug` 能保住，只是因为内存里有它。新程序不能照抄这个写法。
6. **合法值比界面上的三档宽。** `max` 读入时夹到 3–9，界面只提供 5/7/9。`scale` 夹到 80–140，界面只写 90/100/115。
7. **隐藏键 `debug`。** 界面上没有。默认关。
8. **独立的 `pangyi-settings.exe` 曾经有过，现在被安装程序删掉。** `setup.rs` 把安装和设置并进 `pangyi.exe`。升级时会删除安装目录和用户目录里的 `pangyi-settings.exe`，并删掉开始菜单里的「旁译 设置.lnk」。步骤 3 之前，新 exe 不能先放进安装目录，否则下一次安装会把它当旧文件删掉。
9. **现在没有托盘入口，也没有候选窗菜单入口。** 托盘代码在 `ime/src/bin/app.rs`，那是另一套钩子原型，菜单里是「跟随系统 / 自己上屏 / 开机启动 / 退出」，没有设置。TSF 输入法 DLL 不建托盘。候选窗只处理点选上屏。
10. **没有「打开设置」的快捷键。** `Ctrl+.` 翻转中文标点，`Ctrl+,` 循环翻译模式，单击 Shift 翻转英文模式。它们在输入法进程里改内存并 `save()`。
11. **`ime/src/bin/settings_app.rs` 不是安装产物。** 它链接整个 `pangyi_ime`（含内嵌词库），只是开发时开旧面板。CI 编的是 `--bin setup`。
12. **打开短语文件的调用，静态看是错的。** `ShellExecuteW` 的「动作」参数传了 `notepad.exe`，真正的 `"open"` 被丢掉了，返回值也没检查。本文没有在 Windows 上点过，不能说它一定打不开，但新按钮不要照抄参数顺序。
13. **账号窗口已经在源码里，不在已发布的 v4.18.0 安装包里。** 实现在 `ime/src/bin/setup/auth.rs`，Win32 控件 + WinHTTP，只编进带 `account` feature 的 `setup.exe`。README 写明 v4.18.0 安装包还没有这个窗口。
14. **词库统计依赖内嵌表。** `dict::stats()` 数的是编进 DLL 的 `dict.tsv` 和 `lm.tsv`。设置程序若要显示同一个数字，就不能去链接这张表。
15. **CI 没有记录 66 MB / 69 MB 这个测量值。** 脚本只检查下限。
16. **现有设置窗口不是 820×560。** 逻辑尺寸是 360×762，有「关闭」药丸。熊猫和套娃画在每一页的顶栏上，不是只在关于页。
17. **候选窗和设置面板的字体都是微软雅黑 UI。** Segoe UI Variable 是新规格，旧代码里没有。

与已知情况相符、无需更正的部分：Rust 工程；`ime/` 产出 cdylib `pangyi_ime.dll`；64 位 MSVC、32 位 llvm-mingw；安装包是 `ime` 里自写的 `setup`；候选窗和设置面板都是 GDI，没有界面图片；`accent` 是 0..4；产品承诺是输入法本机运行、无广告、DLL 不遥测；推 `v*` 标签会打安装包并上传草稿 Release。

## 5. `settings.txt`

### 5.1 路径

`settings::cfg_file()`：

```text
%LOCALAPPDATA%\Pangyi\settings.txt
```

`LOCALAPPDATA` 没有设置时，退到当前目录下的 `.\Pangyi\settings.txt`。不在 `ProgramData`，也不在安装目录。

同目录里还有这些文件，它们不是 `settings.txt` 的键：

| 文件 | 作用 |
| --- | --- |
| `layout.txt` | 旧版排版。全文 trim 后等于 `h`（忽略大小写）则横排。先读它，再用 `settings.txt` 的 `layout` 覆盖 |
| `updater.json` | 更新程序自己的配置 |
| `account.dat` | DPAPI 加密的登录会话，魔数 `PYAC1` |
| `phrases.txt` | 自定义短语 |
| `user-dict.tsv` / `user-gloss.tsv` | 用户词和用户俄语 |
| `user-dict-warnings.txt` | 用户词读入警告 |
| `learned.txt` | 自学习，`词头 TAB 次数` |
| `packs\` | 表情包和符号包 `*.tsv` |
| `packs-warnings.txt` | 包读入警告 |

### 5.2 编码和格式

- 读：`std::fs::read_to_string`。不是合法 UTF-8 时，**整份文件当作没读到**，各项保持默认。
- 写：`format!` 后直接 `std::fs::write`。UTF-8，无 BOM，换行是 `\n` 不是 `\r\n`。读的时候 `lines()` 两种都能拆。
- 一行一个 `键=值`。键和值都会 `trim`。没有 `=` 的行跳过。值里如果还有 `=`，会留在值里（`splitn(2, '=')`）。
- 同一键出现多次：后一行赢。
- 不认识的键：`load()` 忽略。`save()` 重写时丢掉。
- 写失败被忽略（`let _`）。目录不存在时会 `create_dir_all`。
- 写入不是「写临时文件再改名」。和输入法自己的 `save()` 撞在一起时，后写的人用自己内存里的整份快照盖掉文件。

`save()` 固定写成：

```text
max=9
scale=100
layout=v
theme=0
english=0
debug=0
cnpunct=1
trmode=0
accent=0
emoji=0
```

上面是默认值。布尔写成 `0` 或 `1`。

### 5.3 键

默认值来自 `settings.rs` 里的原子量，文件不存在或某键缺失时就是这些。

| 键 | 含义 | 读入规则 | 界面写入 | 默认 |
| --- | --- | --- | --- | --- |
| `max` | 一页候选个数 | 整数，夹到 3–9。解析失败则保持原值 | 5、7、9 | 9 |
| `scale` | 候选窗字号百分比 | 整数，夹到 80–140 | 90 小、100 标准、115 大 | 100 |
| `layout` | 排版 | 忽略大小写等于 `h` 为横排，其他都是竖排 | `v` 或 `h` | 竖排。若只有旧的 `layout.txt` 且内容为 `h`，则为横排 |
| `theme` | 主题 | 整数，夹到 0–2 | 0 跟随系统，1 浅色，2 深色 | 0 |
| `english` | 英文模式 | `1` 或 `true`（忽略大小写）为开 | `1` / `0` | 关 |
| `debug` | 调试日志 | 同上 | 界面不写。只有内存里已是开时，`save()` 才会写成 1 | 关 |
| `cnpunct` | 中文标点 | 同上 | `1` / `0` | 开 |
| `trmode` | 翻译模式 | 整数，夹到 0–2 | 0 关，1 逐字，2 整句 | 0 |
| `accent` | 配色 | 整数，夹到 0–4 | 0 青，1 粉，2 橙，3 紫，4 绿 | 0 |
| `emoji` | 表情模式 | 同 `english` | `1` / `0` | 关 |

界面上的「当前项」比存储更粗：

- `max` ≤5 显示成 5，≤7 显示成 7，其余显示成 9。所以文件里的 6 会看起来像选中了 7，但在用户再点一次之前，文件里仍是 6。
- `scale` ≤90 显示「小」，≥115 显示「大」，中间都是「标准」。

新程序打开时只按这个规则显示，**不要在打开时把 6 改写成 7**。用户没动的键不要写回去。

`theme` 的 0/1/2 不要和 Slint `ColorScheme` 的枚举数值混用。上游枚举是 `Unknown = 0`、`Dark = 1`、`Light = 2`，和这里的 1=浅色、2=深色正好错开。

### 5.4 新程序的写文件规则

步骤 2 不要调用现有 `save()`，也不要复制「整份覆盖」。

1. 写入前重读文件。
2. 只改用户刚刚动过的那一个键。
3. 不认识的行、注释、`debug`、键的相对顺序都保留。
4. 文件还不存在时，按上表写出全部已知键（含 `debug=0`）。
5. 先写临时文件，再替换，避免写到一半被输入法读走。
6. 布尔仍写 `0`/`1`，这样旧输入法读得懂。不要写成 `true`/`false`，尽管旧代码也认 `true`。
7. 继续用 UTF-8、无 BOM、`\n`。

这是相对旧 `save()` 的加严，不是新格式。旧输入法忽略它不认识的行，所以多留一行是安全的。

## 6. 输入法什么时候重新读设置

有三条路径，都在 `pangyi_ime.dll` 被宿主加载之后，不在设置进程里。

1. **激活。** `TextService::activate`（`ime/src/lib.rs`）调用 `settings::load()`，把全部键读进内存。注释写明必须在打日志之前读，因为日志开关就是 `debug`。
2. **候选窗第一次创建。** `cand::init` 若窗口还在就直接返回；否则 `detect_theme()` 再 `load()` 一次。`detect_theme()` 同时读注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize\AppsUseLightTheme`（值为 0 则系统是深色）和主显示器 DPI。窗口活着的期间不会因为设置文件变了而再建一次。
3. **500 ms 热重载。** `status.rs` 的轮询大约每 500 ms（50 ms 定时器的第 10 拍）看 `settings.txt` 的修改时间。变了只调用 `reload_modes()`，只更新 `english` 和 `emoji`。两个开关在输入法处于激活状态时有变化，会弹出胶囊提示。注释写明其余项故意不重读，避免打字中途改候选数、主题和窗口尺寸时闪烁。

因此：

- 独立 exe 写入 `english` 或 `emoji` 后，正在使用旁译的程序大约半秒内会跟上。这是现成机制，不需要新的窗口消息。
- 写入 `max`、`scale`、`layout`、`theme`、`accent`、`cnpunct`、`trmode`、`debug` 后，**已经打开的宿主不会马上变**。要等这个宿主里的输入法下次 `activate`（通常是切走再切回来，或重新打开那个程序）。新进程第一次建候选窗时会读到新值。
- 旧面板点选项后调用的 `cand::refresh_settings()` 只刷新**设置进程自己**里的候选窗。桌面上的「旁译.exe」和记事本里的输入法不是同一个进程。所以旧面板今天也做不到「记事本里的候选窗立刻改字号」。
- `Ctrl+.`、`Ctrl+,`、单击 Shift 是输入法进程内直接改内存并 `save()`。设置程序随后若用过期内存整份覆盖，会把刚刚的快捷键改动盖掉。所以第 5.4 节的「改前重读、只改一键」是必须的。

规格要求设置即时生效。步骤 2 能做到的即时，只有两件事：设置窗口里的预览，以及已经热重载的英文/表情开关。若要求记事本里的候选窗也立刻改字号、配色、排版、主题，就要改 DLL 里的 `reload_modes()`。那是另一个小 PR，不是步骤 2，也不是联网。默认假设：**步骤 2 不改 DLL。**

`updater.json` 不在这套热重载里。更新开关由更新程序自己读。

### 7.3 字号和排版

候选窗字体：微软雅黑 UI，`CreateFontW` 高度为负。逻辑像素先乘字号百分比再交给 DPI：

```text
像素 = (字号基准 × scale / 100) × dpi / 96
```

除法是整数除法。三档在 96 DPI 下是：

| 界面 | scale | 词 16 | 俄语 12 | 序号 11 |
| --- | --- | --- | --- | --- |
| 小 | 90 | 14 | 10 | 9 |
| 标准 | 100 | 16 | 12 | 11 |
| 大 | 115 | 18 | 13 | 12 |

常量在 `cand.rs`：`TEXT_PX = 16`，`ANNO_PX = 12`，`INDEX_PX = 11`。间距 `PAD = 8`，`GAP = 8`，窗口圆角直径相关的 `WIN_RADIUS = 10`，选中条圆角 `BAR_RADIUS = 8`。俄语显示截断在 44 个字符。

竖排：序号、中文、俄语三列。横排：序号和中文排成一行，当前项的俄语另起一行。预览用两行固定例句，取自 `dict.rs` 里短语模板的原文，不打开 `dict.tsv`：

- 电子邮箱 / электронная почта
- 微信号 / WeChat ID

设置面板自己的字是 12 和 14，不乘 `scale`。新设置窗口的控件字号也不要跟着「候选字号」变；变的只是预览。

### 步骤 3：换入口

单独 PR，至少包括：

- `setup.rs` 安装 `pangyi-settings.exe`，并把它从「旧文件删除名单」里拿掉。
- 桌面「旁译.exe」、开始菜单、安装结束时的「打开设置」改为启动新 exe。旧 GDI 面板不再作为用户入口。
- 卸载时删掉新 exe。
- 发版脚本像对待 `updater/Cargo.toml` 那样同步 `settings/Cargo.toml` 的版本号。
- README「代码：MIT」补上设置程序所用的 Slint 许可，以及关于页里的署名。
- 仍不把 Slint 链进 DLL，不给 DLL 加联网。

可选的后续，不在步骤 2 和 3 里：若要候选窗立刻跟随字号、排版、主题、配色，再改 `reload_modes()` 的重读范围。那是 DLL 行为变更，需要单独确认，因为现有注释故意不在打字中途重读这些项。
